# SmartNewsフィードの枠配分（マッチ棒22 + 他カテゴリ各1）

SmartNews / ママテナ / イチオシ 共通フィード（`/feed/smartnews`）の30枠を、
どのカテゴリにどう配るかの設計と運用メモ。

- **対象**: `https://noutorebiyori.com/feed/smartnews`
- **変更日**: 2026-09-16
- **関連**: `docs/ga4-measurement.md`（効果測定に使うイベント設計）

---

## 1. なぜ変えたか

### 発見した問題

変更前のフィードは、GROQ の並び替えだけで30件を決めていた。

```groq
| order(select(string::startsWith(slug.current, "matchstick-quiz/") => 0, 1) asc,
        publishedAt desc)[0...30]
```

並び替えの第1キーが「マッチ棒なら0、それ以外は1」なので、
**全マッチ棒記事 → その後に他カテゴリ**という順に並ぶ。そこから先頭30件を取る。

マッチ棒は1日5本生成＋`daily-publish.js` が毎日2本を再公開しており、
**在庫が常に30本を大きく超えている**。結果、30枠すべてが最新のマッチ棒で埋まり、
**他カテゴリは構造的に1本も配信されない**状態になっていた。

元のコメントには「配信先が『上位N件のみ取り込む』挙動でもマッチ棒が漏れないように」とあり、
保険のつもりの実装が全枠独占になっていた形。

### GA4 の実測（2026/09/12〜09/14）

|                                         |   表示回数 |   構成比 |
| --------------------------------------- | ---------: | -------: |
| マッチ棒 上位30記事（＝フィードの30枠） |    259,306 |    74.2% |
| マッチ棒 それ以外（検索・サイト内回遊） |     12,571 |     3.6% |
| **マッチ棒以外の全カテゴリ合計**        | **24,460** | **7.0%** |

マッチ棒以外の 24,460 は Gunosy / TRILL / Merkystyle / 検索からの流入で、
**SmartNews経由ではない**。

### 判定できなかったこと

「どのカテゴリがSmartNewsで人気か」は、**他カテゴリを一度も配信していない状態では分からない**。
比較できるのはマッチ棒以外の8カテゴリ同士だけ（全員 Gunosy 等で同条件）で、
その中では クロスワード > 難読漢字 > 四字熟語 が下位グループの10〜15倍あった。

## 2. 変更後の配分

| 位置     | 中身                                     |   件数 |
| -------- | ---------------------------------------- | -----: |
| 1〜10位  | マッチ棒クイズ（最新10本 ≒ 2日分）       |     10 |
| 11〜18位 | デイリー生成の8カテゴリの**最新1本ずつ** |      8 |
| 19〜30位 | マッチ棒クイズ（残り）                   |     12 |
| **合計** |                                          | **30** |

マッチ棒は 30枠 → 22枠（約27%減）。**配信本数は30件のまま**で供給量は落とさない。

探索枠を末尾ではなく中ほどに置いたのは、配信先が「上位N件のみ取り込む」挙動だった場合でも
探索枠が捨てられないようにするため。先頭はマッチ棒で押さえてあるので、どちらの仕様でも損をしない。

### 対象カテゴリ（デイリー生成の8カテゴリ）

`arithmetic-quiz` / `kanji-quiz` / `number-quiz` / `formula-puzzle` /
`crossword-quiz` / `yoji-quiz` / `anagram-quiz` / `mushikui-quiz`

## 3. 安全側の設計

| 仕組み                   | 内容                                                                                                                                                                                     |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **鮮度で自動除外**       | 直近 `FRESHNESS_DAYS`（**7日**）以内に記事があるカテゴリにだけ枠を配る。生成が止まったカテゴリ（`time-quiz` / `money-quiz` / 間違い探し / ビジネスマナー等）の古い記事は自動的に入らない |
| **枠を必ず埋める**       | カテゴリが8個に満たなければマッチ棒で補充。マッチ棒が足りなければ他カテゴリで補充。常に30枠（候補が30件未満のときは出せるだけ）                                                          |
| **カテゴリ枠の上限**     | `MAX_CATEGORY_SLOTS`（8）。カテゴリが増えてもマッチ棒の枠を削りすぎない                                                                                                                  |
| **カテゴリ無しは対象外** | `_type: 'post'` のコラム等はカテゴリ枠を取らない（従来も配信されていなかったので挙動を変えない）                                                                                         |
| **重複排除**             | 同一スラッグの記事は最新1件に寄せる（従来どおり）                                                                                                                                        |

## 4. 実装

| ファイル                               | 役割                                                                        |
| -------------------------------------- | --------------------------------------------------------------------------- |
| `src/lib/rss/feedSlots.js`             | 枠配分の純粋関数（`selectSmartnewsItems`）。設定値もここ                    |
| `src/lib/queries/rssSmartnews.groq.js` | マッチ棒用と非マッチ棒用の2本のクエリ。**絞り込み条件と投影は2本で同一**    |
| `src/routes/feed/smartnews/+server.js` | 2本を並列取得して `selectSmartnewsItems` に渡すだけ                         |
| `tests/feed-slots.test.mjs`            | 配分ロジックのテスト（17件）                                                |
| `tests/smartnews-feed.test.mjs`        | フィード全体のテスト（15件）。`+server.js` を本番と同じコードのまま実行する |

設定を変えたいときは `feedSlots.js` の定数だけを触る。

```js
export const MAX_ITEMS = 30; // 総枠数
export const LEAD_MATCHSTICK_ITEMS = 10; // 先頭のマッチ棒
export const SLOTS_PER_CATEGORY = 1; // 1カテゴリあたりの枠
export const MAX_CATEGORY_SLOTS = 8; // カテゴリ枠の上限
export const FRESHNESS_DAYS = 7; // この日数以内に記事があるカテゴリだけ
```

### item 構造は変えていない

同じ記事集合で変更前後の item XML を突き合わせ、
**両方に含まれる記事の item XML が完全一致**することを確認済み
（`title` / `link` / `guid` / `pubDate` / `description` / `content:encoded` /
`media:thumbnail` / `dc:creator` / `category` / `snf:advertisement` /
`snf:relatedLink` / `snf:analytics`）。変わるのは**どの記事を何番目に出すか**だけ。

記事下の回遊枠（広告枠2 + 本文末3 + 関連記事枠3 の8枠）は
`src/lib/rss/smartnewsRecirculation.js` が担当しており、**今回の変更では触っていない**。
どの記事が配信されるかが変わるだけで、各記事の中身の作られ方は同じ
（`docs/smartnews-recirculation.md`）。

Gunosy / TRILL / Merkystyle のフィードは公開日順のまま。**今回の変更の対象外**。

### コラム（`_type: 'post'`）は配信対象外

カテゴリを持たない記事はカテゴリ枠を取らないため、コラムはフィードに載らない。
これは**変更前から同じ**で（マッチ棒が30枠すべてを占めていたため）、今回の変更で
新たに失われたものではない。配信したくなったら `feedSlots.js` に post 用の枠を足す。

## 5. 効果測定

変更日（2026-09-16）を境に、2週間ごとに比較する。

### 見る数字

**探索 → 自由形式**

- ディメンション: `ページパスとスクリーンクラス`
- 指標: `イベント数`
- フィルタ: `イベント名` = `smartview_page_view`

### 判断

| 指標                              | 意味                                                                 |
| --------------------------------- | -------------------------------------------------------------------- |
| **探索枠の記事1本あたりの閲覧数** | そのカテゴリがSmartNewsで通用するか。**マッチ棒1本あたりと比較する** |
| `smartview_page_view` の総数      | 全体が増えたか減ったか                                               |

| 結果                             | 次の打ち手                                            |
| -------------------------------- | ----------------------------------------------------- |
| 探索枠のカテゴリがマッチ棒に匹敵 | そのカテゴリの `SLOTS_PER_CATEGORY` を増やす          |
| 大きく下回る                     | 枠を1のまま維持（発見のための最小枠として残す）       |
| 総数が落ちた                     | `LEAD_MATCHSTICK_ITEMS` / `MAX_CATEGORY_SLOTS` を戻す |

**一度に1つだけ変えること。** 枠数と並び順を同時に変えると原因が切り分けられなくなる。

### 注意

- マッチ棒の数字には「内容が強い」ぶんと「先頭固定で優遇されている」ぶんが両方含まれる。
  フェアに比較できるのは**探索枠の8カテゴリ同士**。
- 探索枠を作った目的は**最適化ではなく発見**。数字が悪いカテゴリでも、
  枠を完全に0にすると評価の変化に気づけなくなるため、最低1枠は残す方針。
