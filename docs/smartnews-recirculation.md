# SmartNews 記事下の回遊枠

SmartNews（および同一フィードを共有するイチオシ・ママテナ）の記事下に出す枠と、
そこへどの記事を割り当てるかの仕様。

- **フィードURL**: `https://noutorebiyori.com/feed/smartnews`
- **割り当てロジック**: `src/lib/rss/smartnewsRecirculation.js`（SvelteKit 非依存の純粋モジュール）
- **テスト**: `pnpm run test:smartnews`

## なぜこの枠が重要か

SmartView（アプリ内で記事が完結する表示形式）では、`content:encoded` に問題から解答まで
全文を配信している。読者はアプリ内で完結できるため、**noutorebiyori.com の HTML は
読み込まれず、AdSense のタグも動かない**。

記事下のこの回遊枠が、SmartView の読者を自社サイトへ連れてくる唯一の導線になる。

## 枠の内訳（合計8枠）

| 枠                     | 要素                 | 数  | 見え方                     |
| ---------------------- | -------------------- | --- | -------------------------- |
| 広告枠                 | `snf:sponsoredLink`  | 2   | サムネイル付き。最も目立つ |
| 本文末の関連記事リンク | `content:encoded` 内 | 3   | 画像なしテキストリンク     |
| 関連記事枠             | `snf:relatedLink`    | 3   | サムネイル付き             |

> **本文末リンクの3本はガイドライン由来の上限**。SmartFormat の外部リンクガイドライン
> 「NG事例4（最終パラグラフ以降に画像でクイズを出題し遷移させる）」の指摘を受けた経緯があり、
> 「最終パラグラフ以降の関連記事扱い・最大3本・テキストリンク」の形を守る必要がある。
> 画像を付けたり本数を増やしたりしてはいけない。
>
> 広告枠の2件・関連記事枠の3件は**こちらの実装で決めている数字**であり、
> SmartNews 仕様上の上限は未確認。増やせるなら導線をそのまま増やせるので、
> media 窓口に「sponsoredLink / relatedLink はそれぞれ最大何件まで出せるか」を確認したい。

## 記事の割り当て

`allocateRecirculationSlots()` が3つのプールから枠を埋める。

| 表示中の記事 | 広告枠 2       | 本文末 3       | 関連記事枠 3 |
| ------------ | -------------- | -------------- | ------------ |
| マッチ棒以外 | 同カテゴリ 1-2 | 同カテゴリ 3-5 | マッチ棒 1-3 |
| マッチ棒     | マッチ棒 1-2   | マッチ棒 3-5   | マッチ棒 6-8 |

- **関連記事枠はマッチ棒クイズの「推し枠」**。マッチ棒は媒体の売りなので、全記事から
  この枠で送客する。マッチ棒記事自身を表示しているときだけ 6-8 番目にずれる。
- マッチ棒判定は**スラッグの前方一致**（`matchstick-quiz/`）。カテゴリ slug は
  ナビが `matchstick-quiz` / テストスタブが `matchstick` と揺れているため、
  配信クエリの並べ替えと同じくスラッグで判定する。
- マッチ棒以外の記事では**関連記事枠を先に確保する**。同カテゴリのプールが浅いときに
  広告枠のフォールバックへマッチ棒が食われないようにするため。

### 重複の排除

「使用済みスラッグの Set」を1本持ち、枠を順に埋めながら既出をスキップする。これにより

1. 表示中の記事が自分自身をレコメンドする
2. 広告枠・本文末・関連記事枠の間で同じ記事が出る
3. フォールバックで引いた記事が他の枠と被る

がまとめて防げる。**8枠は常にユニーク8記事**になる。

> 以前は本文末リンクと `snf:relatedLink` が同じ `relatedLinks` 配列を回しており、
> 8枠あっても指している記事は5本（うち3本が二重掲載）だった。

### プールが浅いときのフォールバック

同カテゴリ → （関連記事枠はマッチ棒 →）サイト全体の新着、の順に補充する。
カテゴリの記事数が少なくても、カテゴリ未設定の記事でも、空き枠は出ない。

プールの取得件数（`src/routes/feed/smartnews/+server.js`）:

| プール         | クエリ                     | 件数 |
| -------------- | -------------------------- | ---- |
| 同カテゴリ     | `relatedLinks` サブクエリ  | 8    |
| マッチ棒       | `matchstickQuizzesQuery`   | 12   |
| サイト全体新着 | `globalLatestQuizzesQuery` | 12   |

最大で使うのは同カテゴリ5件・マッチ棒8件なので、スキップが出ても枠は埋まる。

## 計測（UTM）

回遊枠のリンクにだけ UTM を付ける。**`item` の `<link>` には付けない**
（SmartFormat 仕様が `<link>` から UTM を除くことを推奨しているため）。

```
utm_source=smartnews
utm_medium=recirculation
utm_campaign=feed
utm_content=sponsoredlink | bodylink | relatedlink
```

`utm_medium` を `referral` ではなく **`recirculation`** にしているのが要点。
SmartView 内の表示は `snf:analytics` に埋め込んだ GA4 タグ経由で
**`smartnews.com / referral`** として記録されるため、medium を分けておかないと
「アプリ内で表示されただけの人」と「実際にサイトへ着地した人」が混ざる。

### GA4 での見方

| 見たいこと                         | 見るもの                                      |
| ---------------------------------- | --------------------------------------------- |
| SmartView 内の表示（サイト未着地） | 参照元/メディア = `smartnews.com / referral`  |
| 実際にサイトへ着地した人           | 参照元/メディア = `smartnews / recirculation` |
| どの枠が効いているか               | 上に `utm_content` を掛け合わせる             |

`smartnews / recirculation` のセッション数が、SmartNews からの**本当の送客数**になる。
AdSense のページビューと桁が合うはずなので、合わなければ別の問題が起きている。

枠ごとのクリック数が出たら、以下を判断できる。

- サムネイル付き枠（sponsoredlink / relatedlink）とテキストリンク（bodylink）のどちらが効くか
- 同カテゴリとマッチ棒推し枠のどちらが選ばれるか
- 関連記事枠をマッチ棒固定にした効果

## 未検証のこと

- **8枠すべてが実際にアプリ上で描画されているか**は未確認。`content:encoded` 内の
  テキストリンク3本は本文HTMLの一部なので確実に出るが、`snf:advertisement` と
  `snf:relatedLink` の描画は SmartNews 側の判断。実機で1本開いて枠数を数えること。
- 関連記事枠をマッチ棒最新1-3で固定しているため、**マッチ棒以外の全記事で同じ3本**が出る。
  露出を最大化する代わりに、複数記事を読む読者には同じ3本が繰り返し見える。
  マッチ棒の本数は足りている（毎日5問更新＋2問再配信）ので、
  `utm_content` の実測を見たうえで、記事ごとに開始位置をずらすローテーションを検討する。
